# board-check: 콘티 검수의 측정 도구

사용자가 정한 순서는 이렇습니다. 이 도구는 그 순서를 **숫자로 확인하는 데** 씁니다.
1. 프롬프트가 콘티와 정확히 맞는가
2. 이미 있는 검수기가 제 역할을 하는가
3. 틀린 것이 자동으로 고쳐지는가
4. 최종 검수

## 지금 들어 있는 것

- **`review.html`**: 컷을 문제 가능성 순서로 보여 주는 검수 화면입니다.
  - 사람이 `1`(통과) / `2`(다시)로 빠르게 판정할 수 있습니다. `j`/`k`로 위아래 이동합니다.
  - 판정은 `feedback.csv`로 내보냅니다. 이 판정이 **정답 자료**가 되고, 이것으로 어떤 검수기든 정확도를 잴 수 있습니다. 기존 검수기도 포함됩니다.
- **`boardcheck.py run`**: 컷마다 비전 모델에 정해진 질문을 던지고 답과 확률을 받습니다(Jev식). 질문은 두 종류입니다.
  - 콘티와 맞는지: 전체, 인물 수, 샷 크기, 행동, 장소, 감정
  - 결함: 손, 얼굴, 몸, 글자·말풍선, 복제 인물, 잘림
  - 선택: 얼굴 신원(h3-multicast `face_check`), 앞 컷과의 옷·머리 일치
- **`boardcheck.py feedback`**: 사람 판정과 비교해 검사 항목마다 정밀도를 냅니다. 모델이 문제라고 한 것 중 사람도 문제라고 한 비율, 그리고 놓친 컷 수입니다.
- **백엔드 두 가지:**
  - `logprobs`: 지금 5678 서버에서 바로 됩니다.
  - `decision`: graydini/llama.cpp의 `/decision` 빌드가 있으면 모든 질문을 한 번에 계산해 훨씬 빠릅니다. 요청 형식은 코드로 확인해 맞췄습니다(`instructions`, `schema`, `contexts`, `images`).

## 기존 검수기(frame_gate) 채점: `gatereview.py`

frame_gate는 339컷 중 312컷을 실패시킨다. 사람 판정과 연결된 기록이 없어서, 그중 몇 개가 진짜 결함인지 아무도 모른다. 이 도구는 사람에게 한 컷씩 물어 **축마다 검수기가 맞은 비율**을 낸다. 서버는 쓰지 않는다.

- `stats --root <gate.json 폴더>`: PASS / 결함 발견 FAIL / 측정 못 함만으로 FAIL / 오류 개수, 축별 통과·실패·미측정·해당없음
- `sample --root <폴더> --out work\gate_review`: 가장 많이 실패시킨 축 5개에서 10컷씩, 측정 못 함만으로 실패한 컷 10, 통과한 컷 10을 골라 `gate_review.html`을 만든다. 그림만 보고 `1` 결함 있음 / `2` 멀쩡함 / `3` 모르겠음. 70컷에 5~10분.
- `score --out work\gate_review --csv gate_votes.csv`: 축마다 맞은 비율과 권고(80% 이상 그대로 막기 / 50~80% 사람 확인 목록 / 50% 미만 막기에서 빼기). `GATE_SCORE.md`에는 축 이름과 개수만 들어간다.
- 그림 경로를 못 찾으면 `--base <프로젝트 폴더>` 또는 `--image-root <그림 폴더>`를 준다.
- **사람 없이:** `referee --out work\gate_review`는 5678 비전 모델이 같은 컷을 다시 본다(글을 쓰지 않고 답 확률만 읽기, 답 순서 두 번). p≥0.8이면 결함, p≤0.2면 멀쩡함, 그 사이는 모르겠음으로 표시한 뒤 곧바로 채점해 `GATE_SCORE_AUTO.md`를 쓴다. 컷당 걸린 초도 함께 적는다. 검수기와 같은 계열 모델이라 정답은 아니고, "검수기 판정이 다시 봐도 유지되는가"를 잰다. costume_lock, seat_order처럼 설정 자료가 있어야 하는 축은 판정하지 않는다.

## 속도

"1컷에 오래 걸리면 안 쓴다"가 기준입니다. 기본값은 빠른 쪽으로 맞춰 두었습니다.
- **핵심 5문항:** 콘티와 맞음, 인물 수, 손, 얼굴, 글자·말풍선만 묻습니다. `--checks full`이면 모든 문항을 묻습니다.
- **질문마다 한 번만 읽습니다.** `--careful`이면 답 순서를 바꿔 두 번 읽습니다.
- **여러 컷을 동시에 보냅니다.** 기본 3컷이고 `--workers`로 바꿉니다. 컷마다 질문은 한 슬롯에서 차례로 가서, 그림 계산을 캐시로 다시 씁니다.
- **추정치:** 지금 서버에서 1컷당 2~4초, `/decision` 빌드에서 1~2초입니다. 실측이 아닙니다. 조사 지시서 S5에서 실제 컷 10개로 잽니다.

## 순서

1. `GLM_TASK_QC_SURVEY.md`: 콘티에서 프롬프트, 그림, 기존 검수기까지의 흐름과 사람이 고친 기록을 조사합니다(읽기만).
2. 조사 결과를 보고 분석 담당이 정합니다.
   - 프롬프트 검사: 생성 **전에** 프롬프트와 콘티를 대조하고, 틀리면 자동으로 다시 씁니다.
   - 기존 검수기를 사람 판정과 대조해 약한 곳을 고칩니다.
   - 실패한 컷을 자동으로 다시 만드는 루프를 붙이고, 재시도 횟수에 상한을 둡니다.
3. 그다음 이 도구를 최종 검수로 씁니다. 이 도구도 같은 방식으로 정확도를 잰 뒤에만 믿습니다.

컷 그림, 콘티 내용, 대사는 `work\`에만 둡니다(`.gitignore`). 올리는 것은 개수만 담은 `summary.md`와 조사 보고서뿐입니다.

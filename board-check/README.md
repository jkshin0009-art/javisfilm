# board-check: 콘티 검수의 측정 도구

사용자가 정한 순서는 이렇습니다. 이 도구는 그 순서를 **숫자로 확인하는 데** 씁니다.
1. 프롬프트가 콘티와 정확히 맞는가
2. 이미 있는 검수기가 제 역할을 하는가
3. 틀린 것이 자동으로 고쳐지는가
4. 최종 검수

## 지금 들어 있는 것

- **`review.html`**: 컷을 문제 가능성 순서로 보여 주는 검수 화면입니다.
  - 사람이 `1`(통과) / `2`(다시)로 빠르게 판정할 수 있습니다. `j`/`k`로 위아래 이동합니다.
  - 판정은 `feedback.csv`로 내보냅니다. 이 판정이 **정답 자료**가 되고, 이것으로 어떤 검수기든 정확도를 잴 수 있습니다. 기존 검수기도 포함됩니다.
- **`boardcheck.py run`**: 컷마다 비전 모델에 정해진 질문을 던지고 답과 확률을 받습니다(Jev식). 질문은 두 종류입니다.
  - 콘티와 맞는지: 전체, 인물 수, 샷 크기, 행동, 장소, 감정
  - 결함: 손, 얼굴, 몸, 글자·말풍선, 복제 인물, 잘림
  - 선택: 얼굴 신원(h3-multicast `face_check`), 앞 컷과의 옷·머리 일치
- **`boardcheck.py feedback`**: 사람 판정과 비교해 검사 항목마다 정밀도를 냅니다. 모델이 문제라고 한 것 중 사람도 문제라고 한 비율, 그리고 놓친 컷 수입니다.
- **백엔드 두 가지:**
  - `logprobs`: 지금 5678 서버에서 바로 됩니다.
  - `decision`: graydini/llama.cpp의 `/decision` 빌드가 있으면 모든 질문을 한 번에 계산해 훨씬 빠릅니다. 요청 형식은 코드로 확인해 맞췄습니다(`instructions`, `schema`, `contexts`, `images`).

## 순서

1. `GLM_TASK_QC_SURVEY.md`: 콘티에서 프롬프트, 그림, 기존 검수기까지의 흐름과 사람이 고친 기록을 조사합니다(읽기만).
2. 조사 결과를 보고 분석 담당이 정합니다.
   - 프롬프트 검사: 생성 **전에** 프롬프트와 콘티를 대조하고, 틀리면 자동으로 다시 씁니다.
   - 기존 검수기를 사람 판정과 대조해 약한 곳을 고칩니다.
   - 실패한 컷을 자동으로 다시 만드는 루프를 붙이고, 재시도 횟수에 상한을 둡니다.
3. 그다음 이 도구를 최종 검수로 씁니다. 이 도구도 같은 방식으로 정확도를 잰 뒤에만 믿습니다.

컷 그림, 콘티 내용, 대사는 `work\`에만 둡니다(`.gitignore`). 올리는 것은 개수만 담은 `summary.md`와 조사 보고서뿐입니다.

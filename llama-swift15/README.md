# Swift 1.5 (Qwen3.8-27B) + MTP, 150K 컨텍스트: llama.cpp 배치 파일

RTX 3090 한 장(GPU0)에서 `llama-server.exe`를 150K 컨텍스트, 8비트 KV 캐시, MTP 추측 디코딩으로 띄우는 배치 파일입니다.
기존 `Swift15-27B-MTP.bat`(2슬롯 × 64K)을 바탕으로 만들었습니다. 모델 경로, 포트 5678, 빌드 경로(`D:\llama.cpp\src_mtp\...`)는 기존 파일과 같습니다.

| 파일 | 하는 일 |
|---|---|
| `Swift15-27B-MTP-150K.bat` | 서버 실행: 150K, 1슬롯, q8_0 KV, MTP. VRAM이 부족하면 자동으로 한 단계 낮춰 다시 시작 |
| `Swift15-bench.bat` | 헬스체크, 설정 확인, 샘플 요청 3개로 속도(tok/s)와 MTP 수락률 측정. 결과를 txt로 저장 |

## 받는 법

1. GitHub에서 이 폴더(`llama-swift15`)를 열고 `.bat` 파일을 클릭합니다.
2. 오른쪽 위의 **Download raw file**(아래 화살표) 버튼을 누릅니다.
3. 받은 파일을 바탕화면 등 아무 곳에나 두면 됩니다. 경로가 파일 안에 절대경로로 들어 있어서 위치는 상관없습니다.
4. 처음 실행할 때 "Windows의 PC 보호" 또는 보안 경고가 뜨면 **추가 정보 → 실행**을 누르세요. 파일 속성에서 **차단 해제**를 체크해 두면 다시 묻지 않습니다.

## 실행 순서

1. 5678 포트를 쓰는 창(기존 Swift/OrcaRouter 서버)을 닫습니다.
2. `Swift15-27B-MTP-150K.bat`을 실행하고, 창에 `model loaded`와 `listening on http://127.0.0.1:5678`이 나올 때까지 기다립니다.
3. `Swift15-bench.bat`을 실행합니다. 150K 전체를 시험하려면 명령 프롬프트에서 `Swift15-bench.bat long`을 실행합니다(프롬프트 처리에 몇 분 걸림).
4. 같은 폴더에 생긴 `swift15_bench_날짜_시간.txt` 내용을 채팅에 붙여 주세요. 결과를 보고 설정을 조정하겠습니다.

## 기존 배치에서 바뀐 점

| 항목 | 기존 `Swift15-27B-MTP.bat` | 새 `...-150K.bat` | 이유 |
|---|---|---|---|
| 컨텍스트 | `-c 131072 -np 2` (요청당 64K) | `-c 150000 -np 1` (요청당 150K) | 목표 150K. MTP는 단일 요청에서만 빨라짐 |
| KV 캐시 | `q4_0` | `q8_0` (8비트) | FP8에 가장 가까운 타입 (아래 참고) |
| MTP 드래프트 KV | 지정 안 함 = f16 | `-ctkd/-ctvd`를 본 KV와 같게 | `-ctk/-ctv`는 드래프트 KV를 바꾸지 않음 |
| 비전(mmproj) | 항상 로드 | 기본 끔 (`VISION=0`) | VRAM을 150K KV에 쓰기 위해서. MTP는 이미지 배치를 건너뜀 |
| VRAM 부족 시 | 같은 설정으로 무한 재시작 | KV 모드를 한 단계 낮춰 재시작, 마지막 단계에서 멈춤 | OOM 방지 |

나머지(`--reasoning-budget`, 샘플링 값, `--spec-draft-n-max 2`, `--fit off`, 포트 확인, VRAM 확인)는 그대로입니다.

### FP8 KV는 llama.cpp에 없습니다

llama.cpp가 받는 KV 타입은 `f32 f16 bf16 q8_0 q4_0 q4_1 iq4_nl q5_0 q5_1`뿐입니다. FP8은 vLLM(HyperQwen) 쪽 옵션입니다.
그래서 같은 8비트인 `q8_0`을 기본값으로 썼습니다. `q8_0-q8_0` FlashAttention 커널은 일반 빌드에도 기본으로 들어 있어서 `build-faq`가 아니어도 됩니다.

### `--gpu-memory-utilization`도 없습니다

llama.cpp는 VRAM 비율을 지정하지 않습니다. 대신 다음 값들의 합으로 결정됩니다.
가중치 + KV(`-c`, `-ctk/-ctv`) + MTP KV(`-ctkd/-ctvd`) + 계산 버퍼(`-b/-ub`) + DeltaNet 상태(`-np` × `--spec-draft-n-max`).
`--fit off`는 llama.cpp가 `-c`나 `-ngl`을 몰래 줄이지 않게 하는 설정이라 그대로 두었습니다.

## KV 모드와 자동 단계 하향

서버가 `out of memory`로 죽으면 다음 모드로 바꿔 다시 시작합니다. 원하는 모드로 바로 시작하려면 명령 프롬프트에서 `set KV_MODE=q4` 다음에 배치를 실행하면 됩니다.

| 순서 | `KV_MODE` | 본 KV (150,000 토큰) | MTP KV | 비고 |
|---|---|---|---|---|
| 1 | `q8` | q8_0/q8_0 ≈ 4,980 MiB | q8_0 ≈ 311 MiB | 기본. 8비트 |
| 2 | `q8k4v` | K q8_0 + V q4_0 ≈ 3,809 MiB | q8_0 ≈ 311 MiB | `build-faq`에서만. 일반 빌드면 건너뜀 |
| 3 | `q4` | q4_0/q4_0 ≈ 2,637 MiB | q4_0 ≈ 165 MiB | 기존 배치와 같은 KV 타입 |
| 4 | `q4ub1k` | q4 + `-ub 1024` | q4_0 | 계산 버퍼 축소. 여기서도 안 되면 멈춤 |

KV 크기는 추정치입니다. Qwen3.8-27B는 64층 중 풀어텐션 16층만 KV를 쓰고(KV 헤드 4개 × 256차원), 나머지 48층(DeltaNet)은 고정 크기 상태만 씁니다. 그래서 토큰당 q8_0 약 34KB, q4_0 약 18KB입니다.
기존 배치 주석의 추정치(약 22,500 MiB)와 비교하면 `q8`은 약 2.5GB가 늘고, 비전을 끄고 슬롯을 1개로 줄여 그중 일부가 줄어듭니다. 24GB에 빠듯하게 들어가거나 넘칠 수 있어서 자동 하향을 넣었습니다.
참고로 커뮤니티 측정에서는 3090 + Q4_K_M + 131K + q8_0 KV + q8_0 드래프트 KV 구성이 올라갔습니다. 지금 모델(UD-Q4_K_S)은 그보다 조금 작습니다.

## 속도 기대치 (100+ TPS 목표에 대해)

llama.cpp로 이 모델을 3090 한 장에서 돌릴 때 150K에서 100 tok/s 이상이 나온 측정은 찾지 못했습니다.
커뮤니티 측정([sudoingX/qwen38-mtp](https://github.com/sudoingX/qwen38-mtp), Qwen3.8-27B, RTX 3090, MTP 없음 → 있음):

| 구성 | MTP 없음 | MTP 있음 |
|---|---|---|
| Q4_K_M, 131K, q8_0 KV, n-max 2 | 41.3 | 63.5 tok/s |
| Q4_K_M, 131K, q4_0 KV, 250W, n-max 4 | 31.9 | 52.8 tok/s |
| UD-Q4_K_XL, 32K, f16 KV, 오버클럭, n-max 2 | 43.9 | 79.6 tok/s |

현실적인 기대치는 짧은 프롬프트에서 60~80 tok/s, 긴 컨텍스트에서 50~65 tok/s 정도입니다. JSON이나 코드처럼 예측하기 쉬운 출력일수록 MTP 수락률이 높아 빨라집니다.
원래 목표치(150K에서 약 95~100 tok/s, 64K에서 127 tok/s)는 HyperQwen(vLLM 패치 + INT4 헤드 + 전용 드래프트 어휘)의 수치이고, llama.cpp에는 그 최적화가 없습니다.

## 잘 안 될 때

- **바로 꺼지고 "server exited before it wrote ..."가 나옴**: 인자를 인식하지 못한 것입니다. 창에 나온 에러 줄을 복사해 주세요. `src_mtp` 빌드가 오래돼 `-ctkd` 같은 옵션을 모를 수 있습니다.
- **q4ub1k에서도 VRAM 부족**: GPU0을 쓰는 다른 프로그램을 닫거나, 파일 위쪽의 `CTX=150000`을 `131072`로 낮추세요.
- **속도 올려 보기**: `SPEC_N=2`를 `3`으로 바꾸고 벤치를 다시 돌려 비교하세요. 수락률이 70% 이상이면 3이 유리할 수 있습니다. 값을 올리면 DeltaNet 상태 메모리가 조금 늘어납니다.
- **이미지 입력이 필요할 때**: `VISION=1`로 바꾸세요. 이때는 `q8`이 안 들어가서 한 단계 낮은 모드로 내려갈 수 있습니다. 비전 입력이 필요하면 기존 `Swift15-27B-MTP.bat`을 쓰는 편이 낫습니다.
